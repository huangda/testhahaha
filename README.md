# 台湾九合一选举 舆情监测 × 选情预测系统

一个可在本机直接执行的选情监测系统：持续抓取台湾选举新闻与 Polymarket 赔率，
用本地规则逐篇分析舆情（情感、议题、候选人声量），再结合加权民调和市场赔率，
生成 22 县市的融合预测、历史趋势与可嵌入网站的赔率卡片。

---

## 一、系统做什么

| 模块 | 内容 |
|---|---|
| **赔率采集** | Polymarket 官方 Gamma API，涵盖 22 县市长 + 全岛政党市场共 23 个事件、82 个候选人市场 |
| **新闻采集** | Google 新闻 RSS（繁中／简中，逐关键字查询）+ 中央社政治／地方／社会／两岸、自由时报、ETtoday、Yahoo 奇摩 |
| **新闻舆情分析** | 本地规则逐篇输出：情感分数、影响强度、涉及县市、候选人个别情感与提及数、议题标签、一句话摘要 |
| **民调采集** | 维基汇总 + 按县市主要候选人定向抓发布方原文；支持度、日期、样本、机构与完整度均保留 |
| **民调数据页** | 展示22县市覆盖状态、发布机构、调查日期、对战组合、支持度、样本、阵营倾向修正及原文链接；可按来源层级和县市筛选 |
| **议员人物卡** | 议员候选人姓名支持鼠标悬停查看中文维基百科简介、头像与完整条目链接；窄屏可点击打开 |
| **民调时效** | 45 天半衰期、60 天截止；原文与转载去重，22 县市输出新鲜度诊断 |
| **事件去重** | 把同一件事的多家转载合并成事件（标题 bigram + 同日 + 候选人重合规则），舆情改以「事件」为单位计算 |
| **关注度参考** | PTT 政黑板贴文与推文数 + 维基百科每日浏览量；只作背景参考，不进入胜率 |
| **市场深度参考** | Polymarket 盘口价差、±5% 挂单深度、24 小时逐笔买卖失衡、单一市场最大持仓占比 |
| **融合预测** | 市场赔率始终为第一锚点；成交与流动性越高，市场权重越高，盘口差时降低信任。新鲜、多来源民调用于校正并考虑阵营及结果方向，新闻只小幅修正；AI统一给出最终胜率，每人最多偏离基础值±5个百分点，最终一位小数且每县市精确合计100.0% |
| **回测校准** | 用 2018 / 2022 共 39 组「民调领先幅度 vs 实际结果」拟合胜率曲线，输出 Brier score 与准确率 |
| **呈现** | 本地 Web Dashboard、方法说明与计算示例、Markdown 报告、JSON 导出、可嵌入网页的候选人赔率卡片 |
| **分析报道** | 一键生成公文式报告（HTML + Word + Markdown），默认用 DeepSeek 润色正文，含4张数据图、选区详情分析、舆情分析和22县市附表 |
| **候选人言论追踪** | 选举黄页身份校验、官方YouTube RSS、选举公报网页文字版、立法院IVOD现成文字记录与新闻引语分来源展示；不扫描PDF、不下载音视频、不做语音转写 |

数据是真的、可重复执行的：每次执行都会写入一笔赔率快照，累积后即可计算 24 小时与一周变化。

## 二、快速开始

便携包已内置所需运行环境。源码方式运行时需 **Python 3.10 以上**，并安装
`python-docx` 与 `Pillow` 以生成 Word 报告和图表。

```powershell
# 1) 执行完整流程（抓赔率 + 抓新闻 + 本地舆情分析 + 预测 + 报告）
.\run.ps1

# 2) 启动 Dashboard（自动挑一个没被占用的端口）
.\serve.ps1
```

Dashboard 会**自动寻找空闲端口**（从 8790 起往后找，全满则由系统随机指派），
启动后在终端输出实际网址并自动打开浏览器，因此在任何电脑上执行都不会因端口冲突而失败。

### 运行流程包含哪些步骤

`python -m tem run` 现在会依序执行：

1. 抓 Polymarket 赔率与新闻（`collect`）
2. 本地规则舆情分析（`analyze`）
3. 补齐外部信号（可用 `--no-market-data` 跳过）：
   民调加权汇总、
   回测校准（首次计算后缓存）、PTT 声量与维基浏览量、盘口深度
4. 融合预测与报告输出（`forecast`）

也可以单独执行任一步骤：

```powershell
python -m tem polls       # 重新解析民调（含对战组合拆分与机构加权）
python -m tem backtest    # 重跑民调到胜率的校准曲线
python -m tem attention   # 抓 PTT 声量与维基浏览量
python -m tem depth       # 抓盘口、逐笔成交与持仓集中度
python -m tem dedupe      # 把转载新闻合并成事件
python -m tem brief       # 生成选情分析报道（HTML + Markdown）
```

Dashboard 顶栏的「分析报道」按钮会即时读取当前资料库状态生成正式报告并开新窗口；
输出 `data/exports/report.html`、`data/exports/report.docx` 与 `data/exports/report.md`。
Word 和网页使用同一套数据图、表格和正文，网页右上角可直接下载 Word 版或另存 PDF。
报告不包含系统概述、方法与数据源或工作建议章节，主体为总体态势、近7天舆情分析、
新北与宜兰重点选情、热点事件和22县市附表。

`polls` 会同时并入新闻民调（`config/polls_media.json`）。首页「重新抓取与分析」
现在会先更新发布方原文民调、合并汇总，再执行新闻分析和预测。想单独更新民调：
该按钮只更新数据、AI胜率与嵌入组件，不生成Word／HTML／Markdown分析报道；
分析报道只在点击顶栏“分析报道”时生成。

首页“重新抓取与分析”默认采集最近 7 天新闻；媒体新闻支持近 7/14/30 天、自定义起止日期，
并按每页 50 则加载，避免一次渲染全部历史新闻。当前筛选范围内的全部结果可批量导出
为 Excel 友好的 CSV，或保留数据结构的 JSON；导出会尝试抓取新闻完整正文并缓存，
同时保留原始摘要、分析摘要与 `full / short / rss-summary / error-fallback` 正文状态。

新闻流的关键词、时间、县市筛选与批量下载均在本地执行。舆情分析使用事件代表稿，
避免同一件事因多家转载被重复计分。

舆情分析提供受控词表的新闻热词云：候选姓名、党派、标准议题和常见选战词语按出现频次、
新闻影响强度与时间范围计算字号，颜色表示加权情感。热词只使用本地统计，不调用 LLM。

舆情分析同时接入新文易数（`tag.observe.tw`）作为外部核对层：读取选举相关新闻事件组、
事件关联报道量、蓝／绿／其他媒体报道家数与外部热词 48 小时走势。相关接口为
`/api/observe/status` 与 `/api/observe/insights`；事件组缓存 30 分钟、热词缓存 10 分钟，
首页完整“重新抓取与分析”会清空外部缓存，下次进入舆情页时重新拉取。
这里的蓝绿份额只表示媒体报道覆盖差异，不是民调支持率，也不会进入胜率公式。个人 Key
可写在 `.env` 的 `TAG_OBSERVE_API_KEY`；不填写时仍可使用每分钟 60 次的公开额度。
外部热词位于独立的“热词趋势”模块：默认展示近 24 小时榜单及 48 小时逐小时折线；
点击单个热词可切换对应折线，页面固定使用 48 小时窗口，避免不同时间口径混用。

“候选人言论追踪”另接四类官方文字来源：选举黄页只用于姓名、2026参选、县市与职务校验；
候选人官方YouTube频道通过RSS读取标题和简介；中选会选举公报只读取“网页格式”文字版；
立法院IVOD只读取页面已存在的会议文字记录。系统不扫描PDF、不做OCR，也不下载音视频或执行
语音转写。来源统一分为“选举公报政见、立法院逐字稿、官方频道信息、新闻直接引语、新闻转述”
五级；只有公报、逐字稿和高质量直接引语可单独支持高可信前后比较，新闻转述不会单独触发
“疑似前后不一致”。

“热点事件追踪”使用新文易数事件组时间线与覆盖详情，展示事件活动强度、媒体报道家数、
报道篇数、按日期从早到晚排列的代表原文及蓝绿报道份额；“议题关系图”使用共同标签与平台
标签分组，连接候选人、政党、县市和议题，所有节点始终显示名称。相关详情按需加载，
接口不可用时退回已缓存事件和本地主题分类。
关系图节点支持拖动，连线会实时跟随，刷新筛选后保留手动位置；“重置布局”可恢复自动排布。
平台标签分组会自动排除早于本届选举年的历史分组，以及“前任／上届／前届／历届”标签组。
关系图保留22县市全部正式县市长候选人，并以虚线连接到所属县市；下拉框只列候选人姓名并按当前
热词热度排序，选择后展示该候选人的县市与关联议题。艺人、歌手、乐团、乐坛、娱乐和影视类标签组
不会进入选举关系图。

```powershell
python -c "from tem.config import load_settings; from tem.pollwatch import collect_media_polls, save_media_polls; save_media_polls(collect_media_polls(load_settings()))"
```

需要固定端口时：

```powershell

.\serve.ps1 -Port 9000 -StrictPort    # 被占用就直接报错，不改用其他端口
.\serve.ps1 -HostAddr 0.0.0.0         # 让同一网段的其他设备也能连接
```

或直接用模块指令：

```powershell
python -m tem run                 # 完整流程
python -m tem serve               # Dashboard
python -m tem status              # 数据状态
python -m tem report              # 在终端输出最新报告
```

> 第一次执行大约需要 20–40 秒（需联网抓取约 20 个新闻来源）。

## 三、舆情分析模式

当前默认使用完全本地的选举规则引擎，不调用外部大模型：57个正面词、81个负面词、
10个否定词、12条选举句式规则和10类议题关键词。系统先切分句子，再识别正负词、
否定关系、候选人姓名和常见选举句式。它可直接离线运行，也不会产生外部 API 费用。

评估过的 CKIP + NTUSD 方案因 PyTorch 运行环境会使便携包增加约 1.45 GB，未纳入当前版本。

## 四、命令一览

```powershell
python -m tem init                     # 初始化数据库
python -m tem collect --days 14        # 只抓赔率与新闻
python -m tem analyze --limit 150      # 只做新闻分析（--force 重新分析）
python -m tem forecast --window 30     # 只做融合预测与报告
python -m tem run                      # 完整流程
python -m tem embed --region 新北市     # 输出指定县市的 Polymarket 嵌入码
python -m tem embed --print-all        # 输出全部 22 县市 + 全岛的嵌入码
python -m tem embed                    # 生成可嵌入网页的候选人赔率卡片
python -m tem roster                   # 解析候选人登记名册（党籍 / 经历）
python -m tem profiles                 # 抓取候选人个人档案（生日 / 简历）
python -m tem polls                    # 解析 22 县市民调汇总表
python -m tem serve                    # Dashboard（--port auto 为默认）
python -m tem status                   # 数据库状态
```

常用参数：

| 参数 | 说明 |
|---|---|
| `--limit N` | 单次最多分析 N 则新闻 |
| `--days N` | 新闻回溯天数（默认 14） |
| `--window N` | 舆情聚合回溯天数（默认 30） |
| `--force` | 重新分析已分析过的新闻 |
| `--no-llm` | 强制使用规则式引擎 |

## 五、Polymarket 接入方式

你原始提供的 `<script type="application/ld+json">` 与 `<figure class="polymarket-embed">` 片段，
是**前端嵌入用**的展示码。系统另外走 **Polymarket 官方 Gamma API**（公开、免密钥）获取结构化数据：

```
GET https://gamma-api.polymarket.com/events?tag_slug=taiwan-elections&closed=false
```

两者使用**相同的 event slug**，所以同一份数据可以同时生成「可计算的数据」与「可贴上网站的嵌入码」。

实测回传 23 个事件：

| 类型 | 事件 |
|---|---|
| 全岛 | `2026-taiwanese-local-elections-party-winner`（国民党 / 民进党 / 民众党） |
| 直辖市长 | 台北、新北、桃园、台中、台南、高雄 |
| 县市长 | 基隆、新竹市、嘉义市、新竹县、苗栗、彰化、南投、云林、嘉义县、屏东、宜兰、花莲、台东、澎湖、金门、连江 |

每个事件内含 30 个市场：**3–6 个真实候选人市场**（有实际报价与成交量），
其余为 `Candidate A…Z` 占位市场（`active=false`，价格固定 0.5）。系统会自动过滤占位市场。

### 产生嵌入码

```powershell
python -m tem embed
```

会生成三个文件：

- `data/exports/polymarket-embeds.html` — 22 县市卡片墙，展开即可复制嵌入码
- `data/exports/polymarket-embeds.json` — 每县市的 JSON-LD 与 `<figure>` 片段
- `data/exports/polymarket-widget.js` — 可直接贴进任何网站的 JS 小工具

## 六、候选人资料卡片与网页嵌入

### Dashboard：候选人详情

凡是带 `data-cand` 属性的候选人名字都可以触发弹窗，目前有三处：

1. **博彩市场政党赔率（全岛）**：候选人对比条上的每一位
2. **22 县市战情板**：点开某个选区后的候选人列表（原来只能点行，现在悬停即可）
3. **选区态势速览**：每张砖上的领先者名字（虚线是悬停提示；点名字查看候选人详情，
   点砖的其他位置仍然进入该选区详情）

弹窗内容：**头像、当前赔率与涨跌、个人资料、加权民调、盘口、新闻舆情、综合胜率形成说明，以及 Polymarket 官方行情组件**。

### 关联新闻弹窗

速览砖上的「📰 新闻数」也是触发器：鼠标移上去（窄屏用点击）会弹出该选区最近的
关联新闻列表，每条带时间、来源、情感分与议题标签，点击直接打开原文。

- 数据来自本地新闻库，按 `GET /api/news?region=台北市&limit=60` 过滤
- 与候选人弹窗互斥，同一时间只显示一个
- 高度超出视口时自动截断并可滚动

### 舆情情感：分两层

系统里「舆情情感」不是一个数，而是两级指标，界面上也分别标注：

| 层级 | 字段 | 含义 | 显示位置 |
|---|---|---|---|
| 候选人级 | `forecasts.news_sentiment` | 只统计**提到该候选人**的新闻，按影响力加权 | 每行候选人名字后面（`+0.18` / `-0.05`） |
| 县市级 | `region_state.avg_sentiment` | 该县市**全部**相关新闻的平均氛围 | 砖底部，标注为「选区 -0.06」 |

砖上原本只显示县市级，看起来像是"情感只给领先者"，其实是每位候选人一直都有，
只是没渲染。现在每行都显示自己的值，鼠标悬停会说明口径。

> 样本很少时两者会接近甚至相同（例如宜兰县只有 2 则新闻，三位候选人被同一批
> 报道同时提及）。候选人级的价值在高新闻量选区最明显——例如桃园市：张善政 -0.07、
> 黄世杰 -0.57，而选区整体 -0.43。

### 个人档案（党籍 / 生日 / 现职 / 简历）

弹窗顶部还会显示候选人档案：

| 字段 | 来源 |
|---|---|
| 党籍 | 候选人登记名册（维基百科 2026 九合一条目）；名册没有时用简介文字解析，再退回 Wikidata P102 |
| 生日 / 年龄 | 维基百科简介首句（`（1978年12月26日—）`）自动解析 |
| 现职 | 简介里的「现任……」 |
| 简历 | 维基百科条目首段；没有条目时用名册的「经历」栏 |
| 头像 / 维基链接 | 维基百科缩图与条目链接 |

数据分两层，互补覆盖：

1. **候选人登记名册**（`config/roster.json`）— 从维基百科
   `2026年中華民國地方公職人員選舉` 条目的「直辖市、县市长」表格解析，22 县市、81 位登记候选人，
   含政党与经历。英文拼音名通过 Wikidata 英文标签自动对上。
2. **个人条目**（`data/cache/profiles/`）— 逐人抓维基百科首段，缓存 7 天。

党籍的补位顺序是四层，越前面优先级越高：

1. `config/roster.json`（维基百科的登记名册，含政党与经历）
2. 维基百科个人条目的简介文字解析（支援「民主进步党新潮流系成员」这类没有「籍」字的写法）
3. `config/candidates_extra.json`（人工核对的补充名册，给登记名册没收录、维基也没条目的人）
4. Wikidata `P102`（政治立场／政党）——用英文名或中文名反查，结果缓存 30 天

跑 `python -m tem profiles --force` 会依序补到第 4 层。目前 72 位候选人**全部都有党籍**，
不再出现空白。

```powershell
python -m tem roster              # 重新解析候选人名册（config/roster.json）
python -m tem profiles            # 批次抓取 / 更新个人档案
python -m tem profiles --force    # 忽略缓存重抓
python -m tem profiles --resolve  # 用 Wikidata 反查缺中文名的候选人，输出建议清单
```

> 抓取时务必用**批次接口**：逐个候选人打维基百科 REST API 会被 429 限流。
> 系统用 `action=query` 一次查 20 条，并对 429 做退避重试。

要给自己页面上的元素加同一个弹窗，只要挂上属性即可被 `TEMPopup.autoBind()` 接管：

```html
<span data-tem-region="TPE" data-tem-candidate="Chiang Wan-an">蒋万安</span>
```

## 七、民调数据

民调采用两层来源：

1. 维基百科 `2026年中華民國直轄市長及縣市長選舉民意調查` 提供带结构的长期汇总；
2. `tem/polldirect.py` 从美丽岛电子报、TVBS、葛瑪蘭新闻网、自由时报、ETtoday、
   中央社及系统 RSS 新闻库中找原文，抓正文后重新计算支持度。Google News
   中转链接会自动还原为发布方原始网址。

```powershell
python -m tem polldirect --days 45 --limit 70  # 定向抓原文民调
python -m tem polls                            # 合并原文与汇总表，写入 config/polls.json
```

原文抓取不是对 129 位候选人逐人请求，而是按 22 个县市各取赔率最高的两名候选人
组合搜索，再在该县市全部候选人白名单中抽取。这样请求量仍约为 22 组，但相关性更高。
所有成功抓取的原文会缓存在 `data/cache/polls/`，网络暂时失败时可回退到最近副本。

已处理的解析问题：

| 问题 | 处理方式 |
|---|---|
| 把「领先/落后/差距」当成支持度 | 排除差距、换算得票率、投票率、满意度等口径 |
| 把议员选区、政党支持者交叉分析当成全市支持度 | 优先全市或全体受访者口径，排除选区和分组样本 |
| 同一篇稿同时含主口径、历史比较与看好度 | 按句法上下文打分，不使用单纯的“第一个百分数” |
| 同一份调查被多家媒体转载 | 按调查机构、日期、样本数、支持度和转载来源去重 |
| 缺失调查日期或原文只做二手引述 | 标记 `full / partial / media-cite` 并降低权重 |
| 样本数含千位分隔符，如 `1,068` | 支持逗号并还原完整整数，避免误读为 `68` |
| 22 个县市字形不一致（台北市 / 臺北市） | 统一县市键后再汇总 |

加权公式保持简单：

```text
单份民调权重 = 机构权重 × 样本量权重 × 完整度权重 × 0.5^(距调查结束天数/45)
```

调查结束超过 60 天不参与加权。输出包括 `latest`（最新一笔）、`average`（近期均值）、
`weighted`（加权值）、来源、样本数、日期与完整度。

主要输出：

- `config/polls_direct.json`：直抓原文、支持度、调查日期、样本数、去重后的转载地址
- `config/polls.json`：直抓原文与维基汇总合并后的最终民调数据
- `data/exports/poll_support.json`：本轮直抓的加权支持度
- `data/exports/poll_coverage.json`：22 县市的新鲜/陈旧/缺失状态
- `data/exports/polls_rejected.json`：未通过校验的稿件的剔除原因

用途：

- **报告**新增「民调 × 赔率对照」表，把民调领先者、民调均值、最新民调与市场概率、融合概率并排
- **候选人弹窗**顶部显示该候选人的民调均值与最新值，可直接和市场赔率对照

> 民调与赔率是两种不同的测量：民调问「你会投给谁」，赔率反映「市场认为谁会赢」。
> 两者并列比单看一项更有信息量，但机构的调查方法、样本与时间差异很大，仅供参考。

## 八、预测方法

```
market_i = Polymarket 各候选人 YES 价 / 同选区加总
market_i' = market_i ^ market_reliability
poll_i   = 同一对战组合的加权民调胜选概率
news_i   = normalize(1 + 0.5 × 新闻情感)
raw_i    = w_market × market_i' + w_poll × poll_i + 0.10 × news_i
fused_i  = raw_i / Σ raw_j
```

两条防护机制：

1. **市场质量决定权重**：高质量市场为 55%/35%/10%，中等市场为 40%/50%/10%，低质量市场为 25%/65%/10%（市场/民调/舆情）。
2. **极端市场概率收缩**：市场可靠度越高，越接近原始赔率；可靠度越低，候选人概率分布越平缓，避免薄弱盘口直接产生九十几的胜率。
3. **样本不足自动收缩**：候选人专属新闻很少时，情感分向所在县市总体舆情靠拢。

分析报道默认调用已配置的 DeepSeek V4 Flash 润色正文。模型只接收系统事实数据，不参与计算；所有数字会与事实数据校验，失败时自动回退模板报告。

完整公式、名词解释和数值示例可在 Dashboard 的「方法数据」页查看。

### 输出指标

- **舆情翻转**：融合后领先者与市场领先者不同
- **胶着选区**：融合领先差距 ≤ 12 个百分点
- **波动大**：近一周任一候选人赔率变动 > 5pt

## 九、调整设置

| 文件 | 用途 |
|---|---|
| `config/regions.json` | 22 县市定义、别名、对应的 Polymarket slug |
| `config/sources.json` | 新闻来源、Google 新闻查询词、选举关键词过滤表、来源权重 |

| `.env` | 外部 API 与预测参数 |

### 补齐中文人名

Polymarket 使用英文拼音。系统内建 40+ 组已确认的对照；未收录者会直接显示英文原名
（例如：`Wen Shih-cheng`、`Lin Kuo-chang`）。
要补上中文，编辑 `config/name_map.json`：

```json
{
  "politicians": {
    "Wen Shih-cheng": "温世政"
  }
}
```

存档后重新执行 `python -m tem run` 即生效（不需重建数据库）。

### 添加新闻来源

在 `config/sources.json` 的 `feeds` 加入：

```json
{
  "id": "my-source",
  "name": "我的新闻源",
  "url": "https://example.com/rss.xml",
  "kind": "rss",
  "lang": "zh-Hant",
  "enabled": true,
  "weight": 1.0
}
```

Google 新闻型来源用 `url_template`，其中 `{q}` 会被 `queries` 逐条代入。

## 十一、注意事项

- **首次执行**只会有一笔赔率快照，「24 小时 / 一周变化」需要累积多次执行才会出现。
  建议用 Windows 工作排程器每天执行一次 `run.ps1`。
- **新闻来源会变**。RSS 端点失效时系统只会略过该来源并输出警告，不会中断；
  若某来源长期失效，请在 `config/sources.json` 将其 `enabled` 设为 `false`。
  （原始设置中的联合报 RSS 已失效，已改以其他来源替代。）
- **规则式引擎的已知限制**：对「A 领先 B」这类相对句式，
  词典引擎可能把正负面同时归给双方。此类句式已加入专门样式规则，
  但反讽、隐喻和复杂因果关系仍需人工复核。
- **免责**：本系统为量化舆情参考工具，所有输出皆为模型推估，
  不构成选举结果预测，也不构成任何投资、交易或投票建议。
